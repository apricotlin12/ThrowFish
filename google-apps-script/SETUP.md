# ThrowFish：Google Apps Script 操作步驟

這份程式已填入你的試算表 ID 與工作表 ID（gid=0），不需要自己修改程式中的網址。這個專案目前已接上你部署的服務，部署網址存於 `src/score-service.ts`；下面步驟保留供重新部署或更新程式使用。GitHub Pages 仍需經你確認後才 push 發布。

## 步驟 1：開啟編輯器

1. 使用擁有這份試算表的 Google 帳號，打開試算表。
2. 點選「擴充功能 → Apps Script」，會開啟程式編輯器。
3. 點左上角「未命名專案」，改成 `ThrowFish 分數服務`。

試算表：<https://docs.google.com/spreadsheets/d/1R_YjVopuqSth7HJ-48nnZGfl6KBnGZO0Pse6GI93PTg/edit?gid=0>

## 步驟 2：貼上程式

1. 開啟本專案 `google-apps-script/Code.gs`，複製整份內容。
2. 在 Apps Script 左側選取預設的 `程式碼.gs` 或 `Code.gs`。
3. 刪除編輯器預設的 `myFunction()` 範例，貼上完整內容。
4. 按儲存或 Ctrl+S。

工作表第 1 列保留以下五個表頭，文字必須相同：

| 暱稱 | 分數 | 空中翻轉 | 高拋路線 | 完美落盤 |
| --- | --- | --- | --- | --- |

程式依表頭對應欄位，不改表頭，也不新增其他資料欄。首次接觸烤盤前的翻轉，每圈 10 分；高拋路線欄存高拋／彈跳共用加分。大於 0 分才可送出，暱稱選填。

## 步驟 3：確認設定並授權

1. 在編輯器上方「選取函式」下拉選單，選 `setupThrowFish`。
2. 按「執行」。不要直接執行 `doPost`，那個函式需要遊戲傳入資料。
3. 若顯示「需要授權」，按「查看權限」，選擇你的 Google 帳號。
4. 確認授權對象是你剛建立的 `ThrowFish 分數服務`，檢查它要求的試算表存取權，再授權。
5. 若你的自建程式顯示「Google 尚未驗證這個應用程式」，可依畫面提供的自建應用程式授權選项繼續。若公司／學校帳號顯示管理員禁止授權，先停止並提供畫面的文字；不要關閉帳號安全設定。
6. 執行記錄出現下面文字，就代表設定檢查成功：

```text
ThrowFish 設定完成：可存取試算表，五個欄位正確。本次未寫入資料。
```

這一步只檢查權限和表頭，**不會新增任何分數**。程式以指定 ID 開啟試算表，因此不需要讓试算表公開。Google 的試算表授權範圍可能涵蓋帳號中的試算表；這份程式只操作程式內指定的這一份。

## 步驟 4：新增部署

1. 點右上角「部署 → 新增部署作業」。
2. 點「選取類型」旁的齒輪，選「網路應用程式」。
3. 填入以下設定（介面文字可能略有差異）：

| 欄位 | 選擇／填入 |
| --- | --- |
| 說明 | `ThrowFish 分數登記與排行榜 v1` |
| 執行身分 | **我／你的 Google 帳號** |
| 誰可以存取 | **任何人，包含未登入 Google 的使用者** |

選擇「任何人」，不要選「任何擁有 Google 帳戶的使用者」，否則玩家可能需要登入。若沒有匿名存取選項，提供畫面的選項文字給 Codex 確認。

4. 點「部署」，如再次要求帳號授權，依步驟 3 檢查後完成。
5. 複製「網路應用程式」網址，格式類似：

```text
https://script.google.com/macros/s/一長串部署識別碼/exec
```

需要的是 **`/exec` 結尾的完整網址**，不是部署 ID、試算表網址、編輯器網址，也不是 `/dev` 測試網址。

## 步驟 5：檢查服務

1. 開啟部署網址，在網址最後加上 `?action=health`。
2. 應看到以下回覆（排版與空白不同沒有關係）：

```json
{"ok":true,"service":"ThrowFish","version":1}
```

3. 再開啟部署網址加上 `?action=leaderboard`，應看到 `ok: true` 與 `leaders` 陣列。例如：

```json
{"ok":true,"leaders":[{"nickname":"","score":80}]}
```

沒有分數時是 `"leaders":[]`，這也是正常結果。用無痕視窗開啟同一個 health 網址，再確認不登入也能看到 `ok:true`。以上兩種檢查皆只讀取資料，不會寫入分數。

如果回覆 `headers_mismatch`，確認第 1 列的五個表頭文字。若是 `service_error`，到 Apps Script 的「執行項目」查看錯誤記錄，將錯誤文字交給 Codex。

## 步驟 6：把部署網址交給 Codex

直接傳送：

```text
部署完成，這是 Apps Script 網址：
https://script.google.com/macros/s/……/exec
```

不用提供密碼、授權權杖或驗證碼。若重新建立服務或更換部署網址，將新網址交給 Codex 更新立即送出、成功確認、失敗重試及前三名讀取，先在本機驗證，依你的要求不直接 push。

## 步驟 7：關閉試算表公開共用

Apps Script 以你的身分執行，因此試算表設為「受限」後仍能寫入。建議等 Codex 串接並驗證後，再到試算表「共用 → 一般存取權 → 受限 → 完成」。不需要把試算表共用给玩家。

此專案的新排行榜已改走 Apps Script，不依賴試算表公開共用。若使用舊的前端版本，需同步更新前端；服務只回傳前三名暱稱與分數，不提供整張表格或修改既有分數的介面。

## 之後修改程式的更新方式

儲存程式不會自動更新既有 `/exec` 服務。修改後到「部署 → 管理部署作業 → 選擇該部署 → 編輯（鉛筆）」，版本選「新增版本」再部署。這樣通常保留相同的部署網址；若另開新部署，需把新網址交給 Codex。

## 程式與串接說明

- `doPost` 接收分數；`doGet` 只供排行榜、服務狀態和寫入確認，不透過 GET 寫入。
- 分數按五個現有表頭寫入。資料一致性檢查包含 0 分拒絕、配分檢查、暱稱文字處理，不代表能防止玩家修改前端後偽造投擲。
- 同時登記時以 Script Lock 避免競爭；在新分數格的註解保存提交 ID，用於重試去重，不增加欄位、不修改既有列。
- GitHub Pages 的跨來源提交不能只用 `no-cors` 的回覆認定寫入成功。前端會以同一提交 ID 查詢寫入確認，得到 `saved` 才顯示成功；同一筆重試沿用 ID。
- 本機驗證涵蓋後端配分與寫入確認流程；部署服務的健康狀態、排行榜與遊戲按鈕即時登記已實際驗證。
